# 2026-11-09 发布验证记录

适用包 v0.2.1-1.85b-ios-fix1；ESP32 0.2.1-1.85b，iOS 0.3.0 源码，核心修复在实体 iPhone 13 Pro / iOS 26.2、Xcode 26.6 上验证。

- 原问题：BLE 已连接、已加密和已订阅通知后，App 的 DEBUG 黄金帧自检报告缺少 navigation.payload，主动断连。
- 原因：原测试向量为 CRLF；Swift 按字面 LF 切分未正确处理 CRLF 字符。改为 Character.isNewline，未跳过编码一致性检查。
- 回归：BLEProtocolGoldenCheckTests 在真实设备执行 1 项测试，涵盖 LF 和 CRLF，0 失败。
- 圆屏：16 MB 整片备份长度核对；三份镜像写入哈希通过；60 秒启动无崩溃，8 MB PSRAM 自检通过；使用者确认画面正常。
- 链路：手机日志确认双阶段握手到 protocol ready；45 秒圆屏采集无断连，LCD DMA 计数持续增加。
- 真实网络：手机初次无法搜索时，私人网络节点离线；用户连接后，从 iPhone 本机调用 App 的真实地点 / 路线 provider，公共地点搜索返回 12 个结果，路线返回 1 条、约 8.36 km，集成检查通过。只用 Mac curl 成功不能代表手机可达。

## 已知限制

- ESP32 镜像保持原 0.2.1，NimBLE 本地 IRK 保存 rc=17/27 警告仍在；连接保持检查不能替代断电重连验收。
- IMU 稳定校准样本不足，精度未验收。
- 在线底图网关仍有 MAP_METADATA_UNAVAILABLE 记录，未将在线底图验证计为通过。
- 手指滑动、长时间后台/锁屏、弱网、实车及道路导航尚未完成验收。
- Windows / Linux 刷机说明没有在对应平台实刷；本次设备端刷写使用 macOS 与 esptool 5.6.0。
- 接收者需要自己的签名和网关配置；没有打包个人签名、Tailscale 地址或访问码，不提供公共导航服务。
- 本次不覆盖 0.3.0-1.85b-arrow 固件的完整端到端兼容性。
